# 🎵 Guess The Song — 香港廣東歌版

> English version: **[README.md](README.md)**

從香港最紅的粵語歌猜歌的多人連線派對遊戲。

- 房主選擇**年份歌單**（每年一個分類）或**歌手精選**（陳奕迅 / 周國賢 / 林家謙 / 三位混合）
- 房主可勾選 **🚫 排除 MIRROR 全部成員**，音樂一下就不會再抽到 MIRROR 系歌曲
- **🔊 音量滑桿**：試聽音樂偏大聲，預設 35%，調整後會記住在裝置上
- 系統產生一組 **6 位房間代碼**，其他玩家用手機加入
- 每回合可選 **10 / 20 / 30 題**：隨機播一首歌的**前 5 秒**
- 4 個選項是**同一位歌手**的歌；先答對的人得分，**答對後 2 秒就進下一首**
- 出題會**輪流平均分配給不同歌手**，同一回合不會有歌手連續出現
- 即時分數排行榜

> 年份分類是**由歌曲的 `year` 自動產生**的（`buildYearCategories()`），
> 所以只要在 `songdata.js` 加歌，對應年份的分類就會自動出現。

> 少數歌在 iTunes 香港沒有試聽，會在載入時自動略過（所以「可玩」可能少 1–2 首）。

## 出題邏輯（為什麼選項不會重複）

早期版本「3 個錯誤選項 = 同一位歌手的其他 3 首」，遇上剛好只有 4 首歌的歌手，
每次抽到他就會出現**一模一樣的 4 個選項**。現在改成：

1. **每位歌手先建立候選池**（最多 8 首同歌手 + 12 首其他），而不是固定 3 首
2. 每次出題從池中隨機抽 3 首，並**避開這個答案最近用過的 8 個選項**
3. **出題順序輪流分配**：一輪一位歌手一首歌，歌手多的先排，
   所以 30 題會盡量涵蓋 20–30 位不同歌手，不會有歌手壟斷

## 🚫 排除 MIRROR 全部成員

年份歌單原本抽到 MIRROR 系歌曲的比例偏高（3 個年份分類共 300 首裡有 107 首，**35.7%**）。
現在選擇歌單的畫面上多了一個開關，按一下就會把 **MIRROR 本團 + 全部 12 位成員**
（陳瑞輝、王智德、楊樂文、邱士縉、江𤒹生、柳應廷、陳卓賢、盧瀚霆、李駿傑、呂爵安、姜濤、邱傲然）
從歌單中排除，**包含合唱曲**（例如「古巨基、呂爵安」也會被排除）。

重點：

- **歌曲資料完全沒有刪除**，MIRROR 的歌還在 `songdata.js` 裡，只是可選擇不玩
- **排除後每個年份分類仍有 41 首以上可玩**（因為已補進 220 首新歌稀釋比例）
- 歌手的「精選」分類不受影響（本來就沒有 MIRROR 的歌）
- 每一類的卡片會即時顯示「已排除 N 首」，讓你看到實際影響

要新增或修改可排除的歌手群組，編輯 `server/songdata.js` 的 `ARTIST_GROUPS`：

```js
export const ARTIST_GROUPS = [
  {
    id: 'mirror',                    // 網址參數用的 id：?exclude=mirror
    label: 'MIRROR',
    description: 'MIRROR 及其全部成員',
    members: ['MIRROR', '陳瑞輝', /* … */]
  }
]
```

## 音源

使用 **iTunes Search API**（免費、免 API key）取得每首歌的 **30 秒試聽**，遊戲只播放前 5 秒。試聽網址會快取在 `server/.preview-cache.json`，第二次啟動秒開。

> iTunes 限制約 **20 次／分鐘**，程式已節流並在遇到 403 時自動等待重試。

### 改完歌單後：補齊試聽快取

新增歌曲後，本機跑一次這個（需要幾分鐘，iTunes 會限流）：

```bash
node server/scripts/warm-cache.mjs        # 抓所有還沒快取的試聽
node server/scripts/check-coverage.mjs    # 檢查哪些歌真的抓不到
```

然後**把 `server/.preview-cache.json` 一起 commit**。這樣部署到 EC2 後分類立刻能玩，
不用等伺服器慢慢抓 iTunes。

## 架構

| 資料夾 | 說明 |
| --- | --- |
| `server/` | Node.js + Express + Socket.io（房間管理、遊戲邏輯、iTunes 音源） |
| `server/scripts/` | 維護工具（試聽快取暖機、覆蓋率檢查） |
| `client/` | React + Vite（手機友善介面） |

## 安裝與執行

需要 Node.js 18+。

```bash
# 1. 安裝所有依賴
npm run install:all

# 2. 啟動開發伺服器（同時啟動 server:3001 與 client:5173）
npm run dev
```

打開瀏覽器到 **http://localhost:5173**。

### 用手機加入

讓其他玩家在同一個 Wi-Fi 下，用手機瀏覽器開啟 `http://<你的電腦IP>:5173`，點「加入朋友的遊戲」輸入房間代碼即可。

> 開發模式下 Vite 已設定 `host: true`，會監聽區域網路。啟動 `npm run dev` 後終端機畫面會列出可用的區域網路位址（例如 `http://192.168.x.x:5173`），用手機開啟那個網址即可。

## 遊戲規則（可調）

- 每回合房主可選 **10 / 20 / 30 題**（若歌單不足則自動調整）
- 每首播放 **前 5 秒**，作答時間最多 **15 秒**
- 每人每首**只能猜一次**；有人答對、或全部人都答錯 → 立即揭曉並換下一首
- **答對後只停 2 秒**就進下一首；全部人答錯則停 4 秒讓人看清楚答案
- 4 個選項 = 正確答案 + **同一位歌手的另外 3 首**（不足時用其他歌手補滿）

這些參數都在 `server/index.js` 頂端：

| 常數 | 預設 | 意思 |
| --- | --- | --- |
| `SONG_SECONDS` | 5 | 每首播幾秒 |
| `GUESS_WINDOW_MS` | 15000 | 作答時間上限 |
| `RESULT_PAUSE_CORRECT_MS` | 2000 | 有人答對後停多久 |
| `RESULT_PAUSE_MS` | 4000 | 沒人答對時停多久 |
| `DISTRACTOR_RECENT` | 8 | 每個答案要避開最近幾個用過的錯誤選項 |

> 開發提示：`npm run dev` 不會在改檔後自動重啟伺服器（避免遊戲中途房間被清空）。
> 需要自動重載時用 `npm run dev:watch`。
>
> 🔍 除錯出題流程：用 `GTS_DEBUG=1 npm run dev`（或 PowerShell 設 `$env:GTS_DEBUG="1"`）
> 會在終端機印出每次出題、每次猜測與結算的細節。

## 生產部署

本機測試生產模式：

```bash
npm run build     # 建置 client 到 client/dist
npm start         # server:3001 同時提供 API + 靜態網頁
```

開啟 **http://localhost:3001**。

### 放到 AWS EC2（讓全世界都能玩）

完整步驟請看 **[DEPLOY.md](DEPLOY.md)**（GitHub 流程，含 nginx + systemd + HTTPS）：

```bash
# 在 EC2 上
git clone https://github.com/alfredkwok/guess-song.git ~/guess-song
cd ~/guess-song && bash deploy/setup.sh   # 首次安裝
bash deploy/update.sh                     # 之後每次更新
```

`deploy/` 內附 `nginx.conf`（含 WebSocket 升級）、`songguess.service`、`setup.sh`、`update.sh`。

## 注意事項

- 部分歌曲在 iTunes 沒有試聽，會自動被過濾；只要分類還有至少 4 首即可玩。
- 第一次載入某分類會需要幾秒鐘去抓試聽，之後有快取就很快。
- 房間在所有人離開後自動清除。
- **排除 MIRROR 是每個房間自己的設定**，不影響其他房間；房間一旦開始就不能再加入。
